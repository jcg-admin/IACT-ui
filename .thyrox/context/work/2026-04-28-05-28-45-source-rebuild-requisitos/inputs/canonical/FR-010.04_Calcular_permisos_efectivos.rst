FR-010.04: Calcular permisos efectivos
======================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE calcular y mostrar los permisos efectivos resultantes
   CUANDO se agregan nuevas funciones, antes de confirmar la asignación.

**Descripción:**

   Cálculo de permisos efectivos:
   
   1. Obtiene funciones actuales del usuario
   2. Agrega funciones nuevas seleccionadas
   3. Expande funciones de agrupadores
   4. Elimina duplicados
   5. Calcula unión de permisos por función
   6. Aplica filtro de segmento
   
   **Estructura de Permisos:**
   
   Cada función otorga permisos sobre:
   
   - Módulo (MOD_xxx)
   - Recurso (endpoint/entidad)
   - Acciones (CREATE, READ, UPDATE, DELETE)
   
   **Preview Visual:**
   
   Mostrar tabla con:
   
   - Permiso actual (ya tenía)
   - Permiso nuevo (se agregará)
   - Origen del permiso (función o agrupador)

----

3. Criterio de Aceptación
-------------------------

::

   DADO funciones seleccionadas para asignar
   CUANDO el sistema calcula permisos efectivos
   ENTONCES muestra preview completo de accesos resultantes
   
   Escenario 1: Preview de permisos
   DADO selección de función REP-001 (ver reportes)
   CUANDO se calcula preview
   ENTONCES se muestra: MOD_Reports - READ
   Y se marca como "NUEVO" (no lo tenía antes)
   
   Escenario 2: Permisos existentes
   DADO usuario con USR-001 (crear usuarios)
   CUANDO se calcula preview
   ENTONCES USR-001 se muestra como "ACTUAL"
   Y nuevos permisos como "NUEVO"
   
   Escenario 3: Permisos vía agrupador
   DADO asignación de AGR-005 con 4 funciones
   CUANDO se calcula
   ENTONCES se muestran las 4 funciones expandidas
   Y se indica origen "vía AGR-005"
   
   Escenario 4: Filtro de segmento aplicado
   DADO usuario con segmento "Centro Norte"
   CUANDO se muestran permisos
   ENTONCES se indica que solo aplican a datos de "Centro Norte"

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:**

Los permisos se suman (unión). No hay permisos negativos
ni denegaciones explícitas en el modelo RBAC Flat.
