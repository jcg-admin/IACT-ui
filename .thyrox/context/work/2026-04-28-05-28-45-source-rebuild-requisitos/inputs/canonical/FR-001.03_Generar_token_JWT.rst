============================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE generar un token JWT válido CUANDO las credenciales
   del usuario han sido verificadas exitosamente.

**Descripción:**

   El sistema genera un token JWT con las siguientes características:
   
   **Estructura del Token:**
   
   - Header: algoritmo HS256
   - Payload:
     - ``sub``: user_id (UUID)
     - ``username``: username del usuario
     - ``roles``: array de códigos de rol
     - ``segment_id``: ID del segmento asignado
     - ``iat``: timestamp de emisión
     - ``exp``: timestamp de expiración (8 horas)
     - ``jti``: identificador único del token (UUID)
   - Signature: firmado con SECRET_KEY del servidor

   **Almacenamiento:**
   
   - El token se registra en tabla ``user_sessions`` (CNST-002)
   - Se almacena: jti, user_id, created_at, expires_at, ip_address, user_agent

----

3. Criterio de Aceptación
-------------------------

::

   DADO un usuario con credenciales verificadas exitosamente
   CUANDO el sistema genera el token JWT
   ENTONCES se crea un token válido con toda la información requerida
   
   Escenario 1: Generación exitosa
   DADO usuario "juan.perez" autenticado
   CUANDO se genera el token
   ENTONCES el token contiene user_id, username, roles, segment_id
   Y el token expira en exactamente 8 horas
   Y se crea registro en user_sessions
   
   Escenario 2: Token único
   DADO dos logins consecutivos del mismo usuario
   CUANDO se generan los tokens
   ENTONCES cada token tiene un jti diferente
   
   Escenario 3: Información de roles
   DADO usuario con roles [ROL-003, ROL-005]
   CUANDO se genera el token
   ENTONCES el claim "roles" contiene ["ROL-003", "ROL-005"]
