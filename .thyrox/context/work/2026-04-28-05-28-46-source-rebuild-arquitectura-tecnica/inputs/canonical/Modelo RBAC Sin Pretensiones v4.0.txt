## Filosofia del Modelo

### Principio Central

Los nombres de funciones deben describir QUE HACE la funcion, no QUIEN es la persona o QUE titulo tiene.

### Por Que Granular

Despues de analizar implementaciones reales en empresas, el enfoque GRANULAR ofrece:

1. Seguridad Maxima: Principio de menor privilegio aplicado al extremo
2. SoD Posible: Puedes separar funciones conflictivas
3. Auditoria Precisa: Sabes exactamente que puede hacer cada quien
4. Escalabilidad: Crece con la organizacion sin refactorizar
5. Cumplimiento: Facilita certificaciones (SOX, ISO 27001, etc)
6. Flexibilidad: Componible como LEGO

### Comparacion

Enfoque Tradicional (Pretencioso):
- CEO
- Director de Finanzas
- Desarrollador Senior
- Service Administrator
- Application Administrator

Problemas:
- Basado en jerarquia organizacional
- Cambio de titulo requiere cambio de roles
- No describe que permisos tiene
- Dificil de auditar

Nuestro Enfoque (Funcional Granular):
- crea_facturas
- aprueba_facturas
- identity:gestiona_aplicaciones
- epm:agrega_miembros
- modifica_codigo

Ventajas:
- Claro que puede hacer
- Titulos organizacionales no afectan RBAC
- Escalable
- Facil auditar
- Cumple regulaciones

## Arquitectura Core

### Componentes Principales

```
Usuario (persona del sistema)
   |
   | tiene asignadas (UA - User Assignment)
   |
   v
Funcion (granular, con namespace opcional)
   |
   | contiene (PA - Permission Assignment)
   |
   v
Capacidad (permiso atomico)
   |
   | sobre
   |
   v
Recurso:Operacion
```

### Definiciones

Persona:
- Representa un usuario del sistema
- Puede tener metadata organizacional (titulo, departamento) SOLO para display
- Esta metadata NO se usa para determinar permisos

Funcion:
- Conjunto granular de capacidades relacionadas
- Nombrada segun patron verbo_sustantivo
- Puede tener namespace (identity, epm, etc)
- Una persona puede tener MULTIPLES funciones

Capacidad:
- Permiso atomico sobre un recurso
- Formato: recurso:operacion
- Ejemplos: facturas:crear, usuarios:leer, grupos:agregar_miembros

Recurso:
- Entidad del sistema sobre la cual se realizan operaciones
- Ejemplos: facturas, usuarios, grupos, archivos, aplicaciones

Operacion:
- Accion que se puede realizar sobre un recurso
- Ejemplos: crear, leer, modificar, eliminar, aprobar

Namespace:
- Prefijo opcional para agrupar funciones de un dominio/producto
- Ejemplos: identity, epm, finanzas
- Evita colisiones entre dominios

## Sistema de Nomenclatura

### Estructura con Namespace

```
[namespace:]verbo_sustantivo[_calificador]

Ejemplos:
- crea_facturas                    (base, sin namespace)
- aprueba_facturas                 (base, sin namespace)
- identity:crea_usuarios           (con namespace identity)
- identity:gestiona_aplicaciones   (con namespace identity)
- epm:agrega_miembros              (con namespace epm)
- epm:sube_archivos                (con namespace epm)
```

### Reglas de Decision

Regla 1: Usa namespace cuando...
- Tienes 50+ funciones totales
- Tienes multiples dominios/productos (identity, epm, etc)
- Existe riesgo de colision de nombres
- Quieres agrupar logicamente funciones

Regla 2: Usa 2 palabras cuando...
- El verbo + sustantivo es claro e inequivoco
- Ejemplos: crea_facturas, aprueba_gastos, elimina_grupos

Regla 3: Usa 3 palabras cuando...
- El objeto es PARTE de otro recurso
- Ejemplos: agrega_miembros_grupos, gestiona_usuarios_aplicaciones
- Hay MULTIPLES tipos del mismo sustantivo
- Ejemplos: ve_reportes_financieros, configura_politicas_seguridad

Regla 4: Sustantivos en plural
- Cuando el recurso es contable: usar plural
- Ejemplos: grupos, usuarios, archivos, facturas

### Catalogo de Verbos Estandar

Creacion:
- crea, genera, registra, inicia

Lectura:
- ve, consulta, lee, lista, busca

Modificacion:
- modifica, actualiza, edita, cambia

Eliminacion:
- elimina, borra, remueve

Aprobacion/Rechazo:
- aprueba, autoriza, valida
- rechaza, deniega, cancela

Gestion:
- gestiona, administra, configura

Ejecucion:
- ejecuta, corre, lanza, procesa

Agregacion/Remocion:
- agrega, anade
- remueve, quita

Importacion/Exportacion:
- importa, exporta, sube, descarga

Monitoreo:
- monitorea, supervisa, observa

### Tablas Principales

#### Tabla: personas

```sql
CREATE TABLE personas (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) UNIQUE NOT NULL,
    nombre_completo VARCHAR(255),
    
    -- Metadata organizacional (NO usado para permisos)
    titulo_organizacional VARCHAR(100),
    departamento VARCHAR(100),
    manager_id UUID REFERENCES personas(id),
    
    -- Estado
    activa BOOLEAN DEFAULT true,
    
    -- Timestamps
    fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    fecha_ultima_modificacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- Metadata
    notas TEXT
);

CREATE INDEX idx_personas_email ON personas(email);
CREATE INDEX idx_personas_activa ON personas(activa);
CREATE INDEX idx_personas_departamento ON personas(departamento);
CREATE INDEX idx_personas_manager ON personas(manager_id);
```

#### Tabla: funciones

```sql
CREATE TABLE funciones (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    
    -- Namespace opcional para dominios
    namespace VARCHAR(50),  -- 'identity', 'epm', NULL para funciones base
    
    -- Nombre de la funcion
    nombre VARCHAR(100) NOT NULL,
    
    -- Nombre completo generado automaticamente
    nombre_completo VARCHAR(200) GENERATED ALWAYS AS (
        CASE 
            WHEN namespace IS NOT NULL THEN namespace || ':' || nombre
            ELSE nombre
        END
    ) STORED,
    
    -- Unique constraint en namespace + nombre
    CONSTRAINT unique_namespace_nombre UNIQUE (namespace, nombre),
    
    -- Descripcion
    descripcion_corta VARCHAR(255),
    descripcion_larga TEXT,
    
    -- Categorizacion
    categoria VARCHAR(50),
    
    -- Metadata
    nivel VARCHAR(50),  -- 'granular', 'completo', 'solo_lectura'
    critico BOOLEAN DEFAULT false,
    
    -- Referencias externas
    oracle_role VARCHAR(255),
    comando_epm VARCHAR(255),
    
    -- Estado
    activa BOOLEAN DEFAULT true,
    
    -- Auditoria
    fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    creada_por UUID REFERENCES personas(id),
    fecha_modificacion TIMESTAMP,
    modificada_por UUID REFERENCES personas(id)
);

CREATE INDEX idx_funciones_namespace ON funciones(namespace);
CREATE INDEX idx_funciones_nombre ON funciones(nombre);
CREATE INDEX idx_funciones_nombre_completo ON funciones(nombre_completo);
CREATE INDEX idx_funciones_categoria ON funciones(categoria);
CREATE INDEX idx_funciones_activa ON funciones(activa);
CREATE INDEX idx_funciones_critico ON funciones(critico);
```

#### Tabla: capacidades

```sql
CREATE TABLE capacidades (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    
    -- Que recurso y operacion
    recurso VARCHAR(100) NOT NULL,
    operacion VARCHAR(50) NOT NULL,
    
    -- Unique constraint en combinacion
    CONSTRAINT unique_recurso_operacion UNIQUE (recurso, operacion),
    
    -- Descripcion
    descripcion TEXT,
    
    -- Scope (JSONB para flexibilidad)
    scope JSONB,
    
    -- Estado
    activa BOOLEAN DEFAULT true,
    
    -- Timestamps
    fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_capacidades_recurso ON capacidades(recurso);
CREATE INDEX idx_capacidades_operacion ON capacidades(operacion);
CREATE INDEX idx_capacidades_activa ON capacidades(activa);
CREATE INDEX idx_capacidades_scope ON capacidades USING GIN (scope);
```

### Tablas de Asignacion

#### Tabla: asignaciones_persona_funcion (UA)

```sql
CREATE TABLE asignaciones_persona_funcion (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    persona_id UUID NOT NULL REFERENCES personas(id) ON DELETE CASCADE,
    funcion_id UUID NOT NULL REFERENCES funciones(id) ON DELETE CASCADE,
    
    -- Constraint: Una persona no puede tener la misma funcion dos veces
    CONSTRAINT unique_persona_funcion UNIQUE (persona_id, funcion_id),
    
    -- Temporal (opcional)
    valida_desde TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    valida_hasta TIMESTAMP,
    
    -- Contexto
    asignada_por UUID REFERENCES personas(id),
    fecha_asignacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    razon TEXT,
    via_bundle VARCHAR(100),  -- Si fue asignada via bundle
    
    -- Estado
    activa BOOLEAN DEFAULT true
);

CREATE INDEX idx_asig_pf_persona ON asignaciones_persona_funcion(persona_id, activa);
CREATE INDEX idx_asig_pf_funcion ON asignaciones_persona_funcion(funcion_id);
CREATE INDEX idx_asig_pf_vigencia ON asignaciones_persona_funcion(valida_hasta) 
    WHERE valida_hasta IS NOT NULL;
CREATE INDEX idx_asig_pf_bundle ON asignaciones_persona_funcion(via_bundle)
    WHERE via_bundle IS NOT NULL;
```

#### Tabla: asignaciones_capacidad_funcion (PA)

```sql
CREATE TABLE asignaciones_capacidad_funcion (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    capacidad_id UUID NOT NULL REFERENCES capacidades(id) ON DELETE CASCADE,
    funcion_id UUID NOT NULL REFERENCES funciones(id) ON DELETE CASCADE,
    
    -- Constraint: Una funcion no puede tener la misma capacidad dos veces
    CONSTRAINT unique_capacidad_funcion UNIQUE (capacidad_id, funcion_id),
    
    -- Contexto
    asignada_por UUID REFERENCES personas(id),
    fecha_asignacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- Estado
    activa BOOLEAN DEFAULT true
);

CREATE INDEX idx_asig_cf_capacidad ON asignaciones_capacidad_funcion(capacidad_id);
CREATE INDEX idx_asig_cf_funcion ON asignaciones_capacidad_funcion(funcion_id, activa);
```

#### Tabla: operaciones_masivas

```sql
CREATE TABLE operaciones_masivas (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),

    registros_fallidos INTEGER DEFAULT 0,
    
    -- Logs
    log_proceso TEXT,
    errores JSONB,
    
    -- Metadata

);

CREATE INDEX idx_op_masivas_iniciada_por ON operaciones_masivas(iniciada_por);
CREATE INDEX idx_op_masivas_estado ON operaciones_masivas(estado);
```

```sql
-- ============================================
-- FUNCIONES: FINANZAS
-- ============================================

INSERT INTO funciones (namespace, nombre, descripcion_corta, categoria, nivel) VALUES
(NULL, 'crea_facturas', 'Crea nuevas facturas en el sistema', 'finanzas', 'granular'),
(NULL, 'aprueba_facturas', 'Aprueba facturas pendientes para pago', 'finanzas', 'granular'),
(NULL, 'aprueba_gastos_grandes', 'Aprueba facturas mayores a $5,000', 'finanzas', 'granular'),
(NULL, 'procesa_pagos', 'Ejecuta pagos de facturas aprobadas', 'finanzas', 'granular'),
(NULL, 've_reportes_financieros', 'Consulta reportes financieros y metricas', 'finanzas', 'solo_lectura');

-- Asignar capacidades
INSERT INTO asignaciones_capacidad_funcion (capacidad_id, funcion_id)
SELECT c.id, f.id
FROM capacidades c, funciones f
WHERE f.nombre = 'crea_facturas' AND f.namespace IS NULL
  AND c.recurso IN ('facturas', 'proveedores')
  AND c.operacion IN ('crear', 'leer');

INSERT INTO asignaciones_capacidad_funcion (capacidad_id, funcion_id)
SELECT c.id, f.id
FROM capacidades c, funciones f
WHERE f.nombre = 'aprueba_facturas' AND f.namespace IS NULL
  AND c.recurso = 'facturas'
  AND c.operacion IN ('aprobar', 'leer');

INSERT INTO asignaciones_capacidad_funcion (capacidad_id, funcion_id)
SELECT c.id, f.id
FROM capacidades c, funciones f
WHERE f.nombre = 'procesa_pagos' AND f.namespace IS NULL
  AND ((c.recurso = 'pagos' AND c.operacion IN ('ejecutar', 'leer'))
   OR (c.recurso = 'facturas' AND c.operacion = 'leer')
   OR (c.recurso = 'cuentas_bancarias' AND c.operacion = 'leer'));

INSERT INTO asignaciones_capacidad_funcion (capacidad_id, funcion_id)
SELECT c.id, f.id
FROM capacidades c, funciones f
WHERE f.nombre = 've_reportes_financieros' AND f.namespace IS NULL
  AND c.recurso IN ('reportes_financieros', 'metricas_financieras')
  AND c.operacion = 'leer';
```

## Operaciones Masivas

### Proceso addUsersToGroup Completo

Proceso para agregar usuarios a un grupo mediante CSV usando epm:agrega_miembros.

#### Paso 1: Validar Precondiciones

```sql
-- Verificar que usuario tiene la funcion epm:agrega_miembros
SELECT * FROM asignaciones_persona_funcion apf
JOIN funciones f ON apf.funcion_id = f.id
WHERE apf.persona_id = 'user-uuid'
  AND f.namespace = 'epm'
  AND f.nombre = 'agrega_miembros'
  AND apf.activa = true;

-- Verificar que archivo CSV existe
SELECT * FROM archivos_epm 
WHERE nombre = 'users_to_add.csv' 
  AND subido_por = 'user-uuid';

-- Verificar que grupo existe
SELECT * FROM grupos_epm 
WHERE LOWER(nombre) = LOWER('Planning_Users');
```

#### Paso 2: Procesar CSV

Pseudocodigo del procesamiento:

```
function procesarAddUsersToGroup(archivoCSV, grupoNombre, usuarioActualId) {
    
    // 1. Crear registro de operacion masiva
    operacionId = db.insert('operaciones_masivas', {
        tipo_operacion: 'agregar_usuarios_grupo',
        nombre_archivo: archivoCSV.nombre,
        ruta_archivo: archivoCSV.ruta,
        tamano_bytes: archivoCSV.tamano,
        contexto: JSON.stringify({ grupo_destino: grupoNombre }),
        iniciada_por: usuarioActualId,
        estado: 'procesando'
    });
    
    // 2. Parsear CSV (columna "User Login" requerida)
    usuarios = parseCSV(archivoCSV, {
        columnas: ['User Login'],
        skipEmptyRows: true,
        trim: true
    });
    
    db.update('operaciones_masivas', {
        total_registros: usuarios.length
    }, { id: operacionId });
    
    // 3. Obtener grupo
    grupo = db.query('SELECT id FROM grupos_epm WHERE LOWER(nombre) = LOWER(?)', [grupoNombre]);
    
    if (!grupo) {
        db.update('operaciones_masivas', { estado: 'fallido', error_mensaje: 'Grupo no existe' });
        throw Error('Grupo ' + grupoNombre + ' no existe');
    }
    
    // 4. Procesar cada usuario
    exitosos = 0;
    fallidos = 0;
    
    for (index = 0; index < usuarios.length; index++) {
        userLogin = usuarios[index]['User Login'];
        numeroLinea = index + 2;  // +2 porque linea 1 es header
        
        try {
            // 4a. Validar usuario existe
            usuario = db.query(
                'SELECT id FROM personas WHERE LOWER(email) = LOWER(?)',
                [userLogin]
            );
            
            if (!usuario) {
                throw Error('Usuario no existe en el dominio de identidad');
            }
            
            // 4b. Validar usuario tiene rol predefinido
            tieneRolPredefinido = db.query(
                'SELECT COUNT(*) > 0 as tiene_rol ' +
                'FROM asignaciones_persona_funcion apf ' +
                'JOIN funciones f ON apf.funcion_id = f.id ' +
                'WHERE apf.persona_id = ? AND f.categoria = "predefinido" AND apf.activa = true',
                [usuario.id]
            );
            
            if (!tieneRolPredefinido.tiene_rol) {
                throw Error('Usuario no tiene rol predefinido asignado');
            }
            
            // 4c. Validar usuario no esta ya en el grupo
            yaEnGrupo = db.query(
                'SELECT COUNT(*) > 0 as ya_existe ' +
                'FROM miembros_grupo_epm ' +
                'WHERE grupo_id = ? AND persona_id = ?',
                [grupo.id, usuario.id]
            );
            
            if (yaEnGrupo.ya_existe) {
                throw Error('Usuario ya es miembro del grupo');
            }
            
            // 4d. Agregar usuario al grupo
            db.insert('miembros_grupo_epm', {
                grupo_id: grupo.id,
                persona_id: usuario.id,
                agregado_por: usuarioActualId,
                fecha_agregado: NOW()
            });
            
            // 4e. Log de auditoria
            db.insert('log_auditoria', {
                persona_id: usuarioActualId,
                accion_tipo: 'agregar_usuario_grupo_epm',
                recurso_tipo: 'grupo_epm',
                recurso_id: grupo.id,
                detalles: JSON.stringify({
                    usuario_agregado: userLogin,
                    grupo: grupoNombre,
                    via: 'operacion_masiva',
                    operacion_id: operacionId
                }),
                exitosa: true
            });
            
            // 4f. Registro exitoso en detalle
            db.insert('operaciones_masivas_detalle', {
                operacion_masiva_id: operacionId,
                numero_linea: numeroLinea,
                datos: JSON.stringify({ user_login: userLogin }),
                exitoso: true
            });
            
            exitosos++;
            
        } catch (error) {
            // Registro fallido en detalle
            db.insert('operaciones_masivas_detalle', {
                operacion_masiva_id: operacionId,
                numero_linea: numeroLinea,
                datos: JSON.stringify({ user_login: userLogin }),
                exitoso: false,
                error_mensaje: error.message
            });
            
            fallidos++;
            
            // Log error a consola
            console.error('Linea ' + numeroLinea + ': Error al agregar "' + userLogin + '" - ' + error.message);
        }
    }
    
    // 5. Finalizar operacion
    duracion = DATEDIFF_SECONDS(NOW(), fecha_inicio);
    
    db.update('operaciones_masivas', {
        estado: 'completado',
        fecha_fin: NOW(),
        registros_exitosos: exitosos,
        registros_fallidos: fallidos,
        duracion_segundos: duracion
    }, { id: operacionId });
    
    // 6. Resumen
    console.log('Operacion completada:');
    console.log('- Total: ' + usuarios.length + ' usuarios');
    console.log('- Exitosos: ' + exitosos);
    console.log('- Fallidos: ' + fallidos);
    console.log('- Duracion: ' + duracion + ' segundos');
    
    if (fallidos > 0) {
        console.log('Revisa la tabla operaciones_masivas_detalle para detalles de errores');
    }
    
    return operacionId;
}
```

## Restricciones SSD

### Concepto

Las restricciones SSD (Static Separation of Duties) previenen que un usuario tenga ciertas combinaciones de funciones que juntas podrian representar un riesgo de seguridad o conflicto de interes.

### Restricciones Base del Sistema

```sql
-- ============================================
-- SSD: FUNCIONES BASE
-- ============================================

INSERT INTO restricciones_ssd (nombre, descripcion, funciones_exclusivas, cardinalidad) VALUES

-- SSD-001: Separacion Crear/Aprobar Facturas
(
    'ssd_crea_aprueba_facturas',
    'Usuario no puede crear Y aprobar facturas (prevencion de fraude)',
    ARRAY[
        (SELECT id FROM funciones WHERE namespace IS NULL AND nombre = 'crea_facturas'),
        (SELECT id FROM funciones WHERE namespace IS NULL AND nombre = 'aprueba_facturas')
    ],
    1
),
```

### Validacion de SSD

```sql
-- Funcion para validar SSD antes de asignar funcion
CREATE OR REPLACE FUNCTION validar_ssd_antes_asignar(
    p_persona_id UUID,
    p_funcion_id UUID
)
RETURNS TABLE (
    valido BOOLEAN,
    restriccion_violada VARCHAR(255),
    mensaje TEXT
) AS $$
DECLARE
    r RECORD;
    funciones_actuales UUID[];
    funciones_propuestas UUID[];
    intersection UUID[];
BEGIN
    -- Obtener funciones actuales de la persona
    SELECT array_agg(funcion_id)
    INTO funciones_actuales
    FROM asignaciones_persona_funcion
    WHERE persona_id = p_persona_id
      AND activa = true;
    
    -- Agregar la funcion propuesta
    IF funciones_actuales IS NULL THEN
        funciones_propuestas := ARRAY[p_funcion_id];
    ELSE
        funciones_propuestas := array_append(funciones_actuales, p_funcion_id);
    END IF;
    
    -- Verificar cada restriccion SSD
    FOR r IN 
        SELECT id, nombre, funciones_exclusivas, cardinalidad
        FROM restricciones_ssd
        WHERE activa = true
    LOOP
        -- Calcular interseccion
        SELECT array_agg(elem)
        INTO intersection
        FROM unnest(funciones_propuestas) elem
        WHERE elem = ANY(r.funciones_exclusivas);
        
        -- Verificar cardinalidad
        IF intersection IS NOT NULL AND array_length(intersection, 1) > r.cardinalidad THEN
            RETURN QUERY SELECT 
                false,
                r.nombre,
                format('Restriccion SSD violada: maximo %s funciones del conjunto permitidas, tiene %s', 
                       r.cardinalidad, 
                       array_length(intersection, 1));
            RETURN;
        END IF;
    END LOOP;
    
    -- Todo OK
    RETURN QUERY SELECT true, NULL::VARCHAR, NULL::TEXT;
END;
$$ LANGUAGE plpgsql;
```

### Funcion para Asignar Bundle

```sql
-- Funcion para asignar bundle completo a una persona
CREATE OR REPLACE FUNCTION asignar_bundle(
    p_persona_id UUID,
    p_bundle_id UUID,
    p_razon TEXT DEFAULT NULL
)
RETURNS TABLE (
    funciones_asignadas INTEGER,
    errores TEXT[]
) AS $$
DECLARE
    v_bundle_nombre VARCHAR(100);
    v_funciones_count INTEGER := 0;
    v_errores TEXT[] := ARRAY[]::TEXT[];
    r RECORD;
    v_validacion RECORD;
BEGIN
    -- Obtener nombre del bundle
    SELECT nombre INTO v_bundle_nombre
    FROM bundles_funciones
    WHERE id = p_bundle_id AND activo = true;
    
    IF v_bundle_nombre IS NULL THEN
        RAISE EXCEPTION 'Bundle no existe o no esta activo';
    END IF;
    
    -- Procesar cada funcion del bundle
    FOR r IN 
        SELECT f.id, f.nombre_completo
        FROM bundle_contiene_funciones bcf
        JOIN funciones f ON bcf.funcion_id = f.id
        WHERE bcf.bundle_id = p_bundle_id
        ORDER BY bcf.orden
    LOOP
        -- Validar SSD
        SELECT * INTO v_validacion
        FROM validar_ssd_antes_asignar(p_persona_id, r.id);
        
        IF v_validacion.valido THEN
            -- Asignar funcion
            INSERT INTO asignaciones_persona_funcion (
                persona_id, 
                funcion_id, 
                razon,
                via_bundle
            )
            VALUES (
                p_persona_id,
                r.id,
                COALESCE(p_razon, 'Asignado via bundle: ' || v_bundle_nombre),
                v_bundle_nombre
            )
            ON CONFLICT (persona_id, funcion_id) DO NOTHING;
            
            v_funciones_count := v_funciones_count + 1;
        ELSE
            -- Registrar error
            v_errores := array_append(v_errores, 
                format('Funcion %s: %s', r.nombre_completo, v_validacion.mensaje));
        END IF;
    END LOOP;
    
    RETURN QUERY SELECT v_funciones_count, v_errores;
END;
$$ LANGUAGE plpgsql;
```

#### Verificar si Persona Puede Realizar Accion

```sql
CREATE OR REPLACE FUNCTION puede_realizar_accion(
    p_persona_id UUID,
    p_recurso VARCHAR(100),
    p_operacion VARCHAR(50)
)
RETURNS BOOLEAN AS $$
DECLARE
    tiene_capacidad BOOLEAN;
BEGIN
    SELECT EXISTS(
        SELECT 1
        FROM capacidades c
        JOIN asignaciones_capacidad_funcion acf ON c.id = acf.capacidad_id
        JOIN asignaciones_persona_funcion apf ON acf.funcion_id = apf.funcion_id
        WHERE apf.persona_id = p_persona_id
          AND c.recurso = p_recurso
          AND c.operacion = p_operacion
          AND apf.activa = true
          AND acf.activa = true
          AND c.activa = true
          AND (apf.valida_hasta IS NULL OR apf.valida_hasta > NOW())
    ) INTO tiene_capacidad;
    
    RETURN tiene_capacidad;
END;
$$ LANGUAGE plpgsql;
```

#### Trigger: Log Automatico

```sql
CREATE OR REPLACE FUNCTION log_auditoria_automatico()
RETURNS TRIGGER AS $$
DECLARE
    v_persona_id UUID;
BEGIN
    -- Intentar obtener persona_id de diferentes campos
    IF TG_OP = 'DELETE' THEN
        v_persona_id := OLD.persona_id;
    ELSE
        v_persona_id := COALESCE(
            NEW.modificada_por, 
            NEW.creada_por, 
            NEW.asignada_por,
            NEW.persona_id
        );
    END IF;
    
    INSERT INTO log_auditoria (
        persona_id,
        accion_tipo,
        recurso_tipo,
        recurso_id,
        detalles,
        exitosa
    ) VALUES (
        v_persona_id,
        TG_OP || '_' || TG_TABLE_NAME,
        TG_TABLE_NAME,
        COALESCE(NEW.id::TEXT, OLD.id::TEXT),
        CASE 
            WHEN TG_OP = 'DELETE' THEN row_to_json(OLD)
            ELSE row_to_json(NEW)
        END,
        true
    );
    
    IF TG_OP = 'DELETE' THEN
        RETURN OLD;
    ELSE
        RETURN NEW;
    END IF;
END;
$$ LANGUAGE plpgsql;
```

```sql
    om.total_registros,
    om.registros_fallidos,
    ROUND((om.registros_fallidos::NUMERIC / om.total_registros) * 100, 2) as porcentaje_error
FROM operaciones_masivas om
WHERE om.estado = 'completado'
  AND om.registros_fallidos > 0
  AND om.total_registros > 0
ORDER BY porcentaje_error DESC
LIMIT 20;
```

### Bundles Mas Usados

```sql
SELECT 
    bf.nombre,
    bf.display_name,
    bf.categoria,
    COUNT(DISTINCT apf.persona_id) as personas_con_bundle,
    (SELECT COUNT(*) FROM bundle_contiene_funciones WHERE bundle_id = bf.id) as num_funciones
FROM bundles_funciones bf
JOIN bundle_contiene_funciones bcf ON bf.id = bcf.bundle_id
JOIN asignaciones_persona_funcion apf ON bcf.funcion_id = apf.funcion_id
WHERE bf.activo = true
  AND apf.activa = true
  AND apf.via_bundle = bf.nombre
GROUP BY bf.id, bf.nombre, bf.display_name, bf.categoria
ORDER BY personas_con_bundle DESC;
```

### Buenas Practicas

#### Principio de Menor Privilegio

Asignar solo las funciones necesarias. No dar accesos innecesarios.

```sql
-- MAL: Dar acceso completo cuando solo necesita lectura
INSERT INTO asignaciones_persona_funcion (persona_id, funcion_id)
VALUES (user_id, (SELECT id FROM funciones WHERE nombre = 'gestiona_usuarios'));

-- BIEN: Dar solo lectura
INSERT INTO asignaciones_persona_funcion (persona_id, funcion_id)
VALUES (user_id, (SELECT id FROM funciones WHERE nombre = 've_usuarios'));
```

#### Usar Bundles para Simplificar

Para usuarios comunes, usar bundles predefinidos.

```sql
-- En vez de asignar 5 funciones manualmente
-- Usar bundle que las incluye todas
SELECT asignar_bundle(
    user_id,
    (SELECT id FROM bundles_funciones WHERE nombre = 'bundle_epm_help_desk'),
    'Help desk EPM'
);
```

#### Revision Periodica

Revisar trimestralmente las asignaciones.

```sql
-- Funciones asignadas hace mas de 1 ano
SELECT 
    p.nombre_completo,
    f.nombre_completo,
    apf.fecha_asignacion,
    age(CURRENT_DATE, apf.fecha_asignacion::date) as antiguedad
FROM asignaciones_persona_funcion apf
JOIN personas p ON apf.persona_id = p.id
JOIN funciones f ON apf.funcion_id = f.id
WHERE apf.activa = true
  AND apf.fecha_asignacion < CURRENT_DATE - INTERVAL '1 year'
ORDER BY apf.fecha_asignacion;
```

#### Validar SSD Siempre

```sql
-- SIEMPRE validar antes de asignar
SELECT * FROM validar_ssd_antes_asignar('persona-uuid', 'funcion-uuid');

-- Solo asignar si pasa validacion
INSERT INTO asignaciones_persona_funcion (persona_id, funcion_id, razon)
SELECT 'persona-uuid', 'funcion-uuid', 'Razon'
WHERE (SELECT valido FROM validar_ssd_antes_asignar('persona-uuid', 'funcion-uuid'));
```

#### Documentar Razones

Siempre llenar el campo razon.

```sql
-- MAL: Sin razon
INSERT INTO asignaciones_persona_funcion (persona_id, funcion_id)
VALUES (user_id, function_id);

-- BIEN: Con razon clara
INSERT INTO asignaciones_persona_funcion (persona_id, funcion_id, razon)
VALUES (
    user_id, 
    function_id,
    'Nuevo miembro del equipo de soporte - necesita agregar usuarios a grupos EPM'
);
```

#### Monitorear Operaciones Masivas

```sql
-- Revisar operaciones con errores
SELECT 
    om.nombre_archivo,
    om.total_registros,
    om.registros_fallidos,
    ROUND((om.registros_fallidos::NUMERIC / om.total_registros) * 100, 2) as porcentaje_error
FROM operaciones_masivas om
WHERE om.estado = 'completado'
  AND om.registros_fallidos > 0
  AND om.fecha_inicio > NOW() - INTERVAL '7 days'
ORDER BY porcentaje_error DESC;
```
