FR-007.04: Registrar cambios en auditoría
=========================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE registrar un evento de auditoría con los valores
   anteriores y nuevos CUANDO se modifica un usuario exitosamente.

**Descripción:**

   El registro incluye:
   
   **Datos del Evento:**
   
   - ``event_type``: 'USER_MODIFIED'
   - ``actor_user_id``: ID del admin que modificó
   - ``target_user_id``: ID del usuario modificado
   - ``timestamp``: Fecha/hora (UTC)
   - ``details``: JSON con cambios detallados
   
   **Estructura de Details (before/after):**
   
   .. code-block:: json
   
      {
        "changes": [
          {
            "field": "full_name",
            "before": "Juan Pérez",
            "after": "Juan Antonio Pérez"
          },
          {
            "field": "status",
            "before": "ACTIVE",
            "after": "INACTIVE",
            "reason": "Baja por renuncia"
          }
        ]
      }

----

3. Criterio de Aceptación
-------------------------

::

   DADO una modificación de usuario exitosa
   CUANDO se completa la transacción
   ENTONCES se registra evento con valores before/after
   
   Escenario 1: Registro de cambios múltiples
   DADO modificación de nombre y email
   CUANDO se registra auditoría
   ENTONCES details.changes contiene 2 elementos
   Y cada elemento tiene field, before, after
   
   Escenario 2: Cambio de estado con motivo
   DADO cambio de status a INACTIVE
   CUANDO se registra
   ENTONCES el cambio de status incluye campo "reason"
   
   Escenario 3: Campos sensibles enmascarados
   DADO cambio de respuesta de seguridad
   CUANDO se registra
   ENTONCES before = "[ENMASCARADO]"
   Y after = "[ENMASCARADO]"
   Y solo se indica que cambió, no los valores
   
   Escenario 4: Consulta posterior
   DADO registro de auditoría existente
   CUANDO se consulta historial del usuario
   ENTONCES se pueden ver todos los cambios realizados

----

4. Reglas y Restricciones
