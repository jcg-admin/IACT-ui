FR-004.04: Invalidar sesiones tras cambio de password
=====================================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE invalidar todas las sesiones activas del usuario
   CUANDO el password ha sido cambiado exitosamente, obligando a
   re-autenticarse con el nuevo password.

**Descripción:**

   El proceso de invalidación post-cambio:
   
   1. Identifica todas las sesiones activas del usuario
   2. Actualiza status a 'PASSWORD_CHANGED' en user_sessions
   3. Agrega todos los tokens a blacklist de Redis
   4. Registra evento de invalidación masiva en auditoría
   5. Redirige al usuario a pantalla de login
   6. Muestra mensaje "Password cambiado. Inicie sesión nuevamente"
   
   **Justificación de Seguridad:**
   
   Si un atacante tenía acceso a una sesión, el cambio de password
   debe revocar ese acceso inmediatamente.

----

3. Criterio de Aceptación
-------------------------

::

   DADO un cambio de password exitoso
   CUANDO se completa la actualización en BD
   ENTONCES todas las sesiones del usuario se invalidan
   
   Escenario 1: Sesión actual invalidada
   DADO usuario que acaba de cambiar password
   CUANDO intenta continuar navegando
   ENTONCES es redirigido a login
   Y debe autenticarse con nuevo password
   
   Escenario 2: Otras sesiones invalidadas
   DADO usuario con sesiones en múltiples dispositivos
   CUANDO cambia password desde uno de ellos
   ENTONCES todas las otras sesiones se cierran
   Y cualquier request retorna 401
   
   Escenario 3: Registro en auditoría
   DADO invalidación de sesiones por cambio de password
   CUANDO se completa
   ENTONCES existe registro con event_type = 'SESSIONS_INVALIDATED'
   Y reason = 'PASSWORD_CHANGE'
   Y count = número de sesiones cerradas
   
   Escenario 4: Blacklist actualizada
   DADO tokens de sesiones cerradas
   CUANDO se agregan a blacklist
   ENTONCES cualquier uso posterior retorna 401

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:**
  - CNST-002: Gestión de sesiones en BD
  - CNST-009: Auditoría

**Proceso Atómico:**

La actualización de password y la invalidación de sesiones deben
ser parte de la misma transacción. Si falla la invalidación,
no se debe completar el cambio de password.
