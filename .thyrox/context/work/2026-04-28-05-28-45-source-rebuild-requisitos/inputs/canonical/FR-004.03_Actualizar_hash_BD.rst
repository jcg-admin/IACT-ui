================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE actualizar el hash del password en la base de datos
   CUANDO el nuevo password ha sido validado exitosamente.

**Descripción:**

   El proceso de actualización:
   
   1. Genera hash bcrypt del nuevo password (cost=12)
   2. Guarda hash anterior en tabla ``password_history``
   3. Actualiza campo ``password_hash`` en tabla ``users``
   4. Actualiza ``password_changed_at = NOW()``
   5. Si ``must_change_password = true``, cambia a ``false``
   6. Registra evento en auditoría (sin el password)
   
   **Almacenamiento de Historial:**
   
   Se guardan los últimos 5 hashes para prevenir reutilización:
   
   - Tabla: ``password_history``
   - Campos: user_id, password_hash, created_at

----

3. Criterio de Aceptación
-------------------------

::

   DADO nuevo password validado correctamente
   CUANDO el sistema actualiza la base de datos
   ENTONCES el hash se almacena y el historial se actualiza
   
   Escenario 1: Actualización exitosa
   DADO password que cumple requisitos
   CUANDO se guarda
   ENTONCES users.password_hash contiene nuevo hash
   Y users.password_changed_at = NOW()
   Y password_history contiene hash anterior
   
   Escenario 2: Historial limitado a 5
   DADO usuario con 5 passwords en historial
   CUANDO cambia password nuevamente
   ENTONCES el más antiguo se elimina del historial
   Y el nuevo se agrega al final
   
   Escenario 3: Cambio forzado completado
   DADO usuario con must_change_password = true
   CUANDO cambia password exitosamente
   ENTONCES must_change_password = false
   
   Escenario 4: Transacción atómica
   DADO cualquier error durante actualización
   CUANDO falla algún paso
   ENTONCES se hace rollback completo
   Y el password anterior sigue vigente
