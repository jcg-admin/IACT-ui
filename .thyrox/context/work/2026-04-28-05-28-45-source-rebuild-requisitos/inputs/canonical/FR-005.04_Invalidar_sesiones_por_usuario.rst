FR-005.04: Invalidar todas las sesiones de un usuario
=====================================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE permitir cerrar todas las sesiones activas de un
   usuario específico CUANDO el administrador de seguridad lo solicita.

**Descripción:**

   El proceso de cierre masivo por usuario:
   
   1. Admin selecciona opción "Cerrar todas las sesiones" para un usuario
   2. Sistema muestra resumen: número de sesiones a cerrar
   3. Admin confirma con advertencia de impacto
   4. Sistema invalida todas las sesiones activas del usuario
   5. Sistema agrega todos los tokens a blacklist
   6. Sistema registra evento único con conteo de sesiones cerradas
   7. Sistema actualiza listado
   
   **Casos de Uso:**
   
   - Usuario reporta compromiso de cuenta
   - Terminación de empleado
   - Sospecha de actividad maliciosa
   - Mantenimiento de seguridad

----

3. Criterio de Aceptación
-------------------------

::

   DADO admin gestionando sesiones
   CUANDO solicita cerrar todas las sesiones de un usuario
   ENTONCES se invalidan todas tras confirmación
   
   Escenario 1: Cierre masivo exitoso
   DADO usuario con 3 sesiones activas
   CUANDO admin confirma cierre masivo
   ENTONCES las 3 sesiones cambian a 'FORCED_LOGOUT'
   Y los 3 tokens se agregan a blacklist
   Y se crea 1 registro de auditoría con count = 3
   
   Escenario 2: Confirmación con resumen
   DADO solicitud de cierre masivo
   CUANDO se muestra confirmación
   ENTONCES indica "Se cerrarán X sesiones del usuario Y"
   Y advierte que el usuario deberá re-autenticarse
   
   Escenario 3: Usuario sin sesiones activas
   DADO usuario sin sesiones activas
   CUANDO admin intenta cierre masivo
   ENTONCES se muestra "El usuario no tiene sesiones activas"
   
   Escenario 4: No afecta sesión del admin ejecutor
   DADO admin ejecutando cierre de sus propias sesiones
   CUANDO confirma
   ENTONCES se cierran todas EXCEPTO la sesión actual
   Y se advierte que no incluye sesión actual

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:**
  - CNST-002: Gestión de sesiones
  - CNST-009: Auditoría obligatoria

**Consideraciones:**

- Operación atómica: todas o ninguna
- Si el admin cierra sus propias sesiones, se excluye la actual
- Notificación opcional al usuario afectado (futuro)
