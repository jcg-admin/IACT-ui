FR-002.01: Invalidar token JWT
==============================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE invalidar el token JWT activo CUANDO el usuario
   solicita cerrar su sesión y confirma la acción.

**Descripción:**

   El proceso de invalidación incluye:
   
   1. Extraer el jti (JWT ID) del token actual
   2. Buscar registro en tabla ``user_sessions`` por jti
   3. Actualizar status de 'ACTIVE' a 'LOGGED_OUT'
   4. Registrar timestamp de cierre (logged_out_at)
   5. Agregar jti a blacklist de tokens (cache Redis)
   
   **Blacklist de Tokens:**
   
   - Los tokens invalidados se agregan a Redis
   - TTL igual al tiempo restante de expiración del token
   - Toda validación de token consulta blacklist primero

----

3. Criterio de Aceptación
-------------------------

::

   DADO un usuario con sesión activa
   CUANDO solicita cerrar sesión y confirma
   ENTONCES el token JWT queda invalidado inmediatamente
   
   Escenario 1: Cierre exitoso
   DADO usuario con token válido
   CUANDO confirma cierre de sesión
   ENTONCES el registro en user_sessions cambia a status = 'LOGGED_OUT'
   Y el token se agrega a la blacklist
   Y cualquier request posterior con ese token retorna 401
   
   Escenario 2: Token ya en blacklist
   DADO token que ya fue invalidado
   CUANDO se intenta usar
   ENTONCES retorna 401 Unauthorized
   Y mensaje "Sesión expirada o inválida"
   
   Escenario 3: Cierre sin confirmar
   DADO usuario que cancela confirmación
   CUANDO no confirma el cierre
   ENTONCES el token permanece válido
   Y la sesión continúa activa

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:**
  - CNST-002: Gestión de sesiones en BD

**Consideraciones de Performance:**

- Blacklist en Redis para consulta O(1)
- TTL automático evita crecimiento indefinido
- Fallback a BD si Redis no disponible
