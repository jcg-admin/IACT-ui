2. Especificación
-----------------

**Declaración:**

   El sistema DEBE verificar las credenciales del usuario contra la base
   de datos CUANDO el formato de username ha sido validado exitosamente.

**Descripción:**

   El sistema realiza la verificación de credenciales:
   
   1. Busca el usuario por username en la tabla ``users``
   2. Verifica que el usuario exista y esté activo (status = 'ACTIVE')
   3. Compara el hash del password ingresado con el almacenado
   4. Verifica que la cuenta no esté bloqueada (BR_015)
   5. Si las credenciales son válidas, continúa el flujo
   6. Si son inválidas, incrementa contador de intentos fallidos

**Algoritmo de Hash:**

   - Algoritmo: bcrypt
   - Cost factor: 12
   - Salt: generado automáticamente por bcrypt

----

3. Criterio de Aceptación
-------------------------

::

   DADO un usuario con credenciales en formato válido
   CUANDO el sistema verifica contra la base de datos
   ENTONCES retorna resultado de autenticación
   
   Escenario 1: Credenciales válidas
   DADO username = "juan.perez" con password correcto
   CUANDO se verifican las credenciales
   ENTONCES el sistema retorna autenticación exitosa
   Y el contador de intentos fallidos se resetea a 0
   
   Escenario 2: Password incorrecto
   DADO username = "juan.perez" con password incorrecto
   CUANDO se verifican las credenciales
   ENTONCES el sistema retorna error de autenticación
   Y el contador de intentos fallidos se incrementa en 1
   Y se muestra "Credenciales incorrectas"
   
   Escenario 3: Usuario no existe
   DADO username = "usuario_inexistente"
   CUANDO se verifican las credenciales
   ENTONCES el sistema retorna error de autenticación
   Y se muestra "Credenciales incorrectas" (mensaje genérico)
   
   Escenario 4: Cuenta bloqueada
   DADO username con 5+ intentos fallidos en últimos 30 minutos
   CUANDO se verifican las credenciales
   ENTONCES el sistema muestra "Cuenta bloqueada. Intente en 30 minutos"

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:**
  - BR_015: Bloqueo tras 5 intentos fallidos en 30 minutos
  
- **CNST aplicables:**
  - CNST-002: Gestión de sesiones en BD
  - CNST-005: Seguridad DRF

**Notas de Seguridad:**

- Tiempo de respuesta constante para prevenir timing attacks
- No revelar si el usuario existe o no
- Passwords nunca se loguean (CNST-009)
- Usar comparación segura de strings
