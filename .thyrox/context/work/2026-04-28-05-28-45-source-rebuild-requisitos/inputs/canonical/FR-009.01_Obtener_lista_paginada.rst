2. Especificación
-----------------

**Declaración:**

   El sistema DEBE obtener y mostrar una lista paginada de usuarios
   CUANDO el actor accede a la funcionalidad de listar usuarios.

**Descripción:**

   El listado incluye:
   
   **Columnas Mostradas:**
   
   - Username
   - Nombre completo
   - Email
   - Estado (ACTIVE/INACTIVE)
   - Último acceso
   - Roles asignados (resumen)
   
   **Paginación:**
   
   - Tamaño de página: 20 usuarios (configurable)
   - Navegación: primera, anterior, siguiente, última
   - Indicador de página actual y total
   - Total de registros encontrados
   
   **Filtro por Segmento:**
   
   El usuario solo ve usuarios de su segmento, a menos que tenga
   permisos de administrador global.

----

3. Criterio de Aceptación
-------------------------

::

   DADO un actor con permisos de listar usuarios
   CUANDO accede a la funcionalidad
   ENTONCES ve lista paginada según su segmento
   
   Escenario 1: Lista inicial
   DADO actor con acceso
   CUANDO carga la vista
   ENTONCES ve primera página con 20 usuarios máximo
   Y ve conteo total de usuarios
   Y puede navegar entre páginas
   
   Escenario 2: Paginación funcional
   DADO 50 usuarios en el sistema
   CUANDO se navega a página 2
   ENTONCES se muestran usuarios 21-40
   Y se actualiza indicador de página
   
   Escenario 3: Filtro de segmento automático
   DADO actor con segmento "Centro Norte"
   CUANDO lista usuarios
   ENTONCES solo ve usuarios de "Centro Norte"
   Y no ve usuarios de otros segmentos
   
   Escenario 4: Admin global
   DADO actor con rol admin_sistema
   CUANDO lista usuarios
   ENTONCES ve todos los usuarios de todos los segmentos

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:**
  - CNST-007: Límites de performance (paginación obligatoria)

**Performance:**

- Consulta optimizada con índices
- No cargar más de 20 registros por request
- Lazy loading de datos relacionados (roles)
