## 3. TÉCNICA 2: MODELO DE LARMAN

### 3.1 Introducción a Técnicas de Larman

Craig Larman, en su libro "Applying UML and Patterns", proporciona técnicas sistemáticas para identificar Casos de Uso desde la perspectiva de eventos del sistema y responsabilidades.

**Concepto clave:** Análisis orientado a EVENTOS vs análisis orientado a DATOS

```
Análisis orientado a DATOS (CRUD - Técnica 1):
  Pregunta: ¿Qué entidades existen?
  Resultado: UC para mantener datos

Análisis orientado a EVENTOS (Larman - Técnica 2):
  Pregunta: ¿Qué puede pasar en el sistema?
  Resultado: UC para responder a eventos
```

#### Las 3 Subtécnicas de Larman

```
SUBTÉCNICA 2.1: Eventos del Sistema
  Identificar eventos externos que sistema debe responder
  Evento significativo → Caso de Uso
  
SUBTÉCNICA 2.2: Operaciones del Sistema
  Identificar operaciones que sistema debe proveer
  Categorizar por tipo: Consulta, Proceso, Config, Integración
  
SUBTÉCNICA 2.3: Responsabilidades del Sistema
  Identificar qué responsabilidades tiene el sistema
  Categorizar: Autenticación, Reportería, Auditoría, etc.
```

### 3.2 SUBTÉCNICA 2.1: Eventos del Sistema

#### Definición

**Evento del Sistema:** Ocurrencia externa que requiere respuesta del sistema

**Características:**
- Iniciado por actor externo (humano, sistema, tiempo)
- Sistema debe responder de alguna manera
- Tiene significado en el dominio del negocio

#### Proceso de Identificación (4 pasos)

```
PASO 1: Identificar Actores Externos
  - Usuarios (por rol)
  - Sistemas externos
  - Tiempo (eventos automáticos)

PASO 2: Por Cada Actor, Listar Eventos que Genera
  Pregunta: ¿Qué puede INICIAR este actor?

PASO 3: Filtrar Eventos Significativos
  - Evento tiene consecuencia relevante
  - Evento no es trivial
  - Evento no está ya cubierto por CRUD

PASO 4: Evento → UC (si no existe ya)
  Generar UC nuevo o verificar si ya existe
```

#### UC-63: Consultar Disponibilidad de Producto (COMPLETO)

```
═══════════════════════════════════════════════════════════════
                    CASO DE USO: UC-63
═══════════════════════════════════════════════════════════════

ID: UC-63
Nombre: Consultar Disponibilidad de Producto
Actor Primario: Estudiante (Solicitante)

Descripción:
  Permite verificar disponibilidad actual de un producto antes
  de crear solicitud, mostrando stock disponible y próximo vencimiento.

Precondiciones:
  1. Usuario autenticado
  2. Al menos un producto existe en catálogo

Trigger: Usuario selecciona "Verificar Disponibilidad"

───────────────────────────────────────────────────────────────
FLUJO NORMAL
───────────────────────────────────────────────────────────────

1. Usuario selecciona opción "Verificar Disponibilidad"

2. Sistema muestra campo de búsqueda:
   "Buscar producto por nombre o CAS Number"

3. Usuario ingresa texto de búsqueda (mínimo 3 caracteres)

4. Sistema busca productos que coincidan:
   SELECT p.id, p.nombre, p.cas_number,
          p.stock_actual, p.unidad_medida,
          p.ubicacion, p.estado,
          COALESCE(SUM(s.cantidad), 0) as stock_reservado
   FROM Producto p
   LEFT JOIN Solicitud s ON p.id = s.producto_id
     AND s.estado IN ('Pendiente', 'Aprobada')
   WHERE p.estado = 'activo'
     AND (p.nombre LIKE '%[texto]%' 
          OR p.cas_number LIKE '%[texto]%')
   GROUP BY p.id
   LIMIT 10

5. Sistema calcula disponibilidad por producto:
   stock_disponible = stock_actual - stock_reservado

6. Sistema muestra resultados en tabla:
   Columnas:
     - Nombre
     - CAS Number
     - Stock Disponible (destacado con color)
     - Unidad
     - Estado Badge
     - [Ver Detalles] [Solicitar]

7. Sistema aplica reglas de visualización:
   IF stock_disponible > 0:
     Badge: "Disponible" (verde)
   ELSIF stock_actual > 0 AND stock_disponible = 0:
     Badge: "Reservado Totalmente" (amarillo)
   ELSIF stock_actual = 0:
     Badge: "Agotado" (rojo)

8. Usuario selecciona producto de interés

9. Sistema consulta información extendida:
   9.1 Próximo vencimiento:
       SELECT MIN(fecha_vencimiento) as proximo_vencimiento
       FROM Contenedor
       WHERE producto_id = ?
```
