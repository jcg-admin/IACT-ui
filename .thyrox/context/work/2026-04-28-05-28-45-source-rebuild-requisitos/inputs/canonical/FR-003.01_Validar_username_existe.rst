FR-003.01: Validar username existe
==================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE validar que el username proporcionado existe y tiene
   cuenta activa CUANDO el usuario solicita recuperar su password.

**Descripción:**

   El sistema realiza la validación:
   
   1. Recibe username del formulario de recuperación
   2. Busca en tabla ``users`` por username exacto
   3. Verifica que el usuario exista
   4. Verifica que status = 'ACTIVE'
   5. Verifica que tenga pregunta de seguridad configurada
   
   **Seguridad - Mensajes Genéricos:**
   
   Para evitar enumeración de usuarios, si el username no existe o está
   inactivo, el sistema muestra un mensaje genérico que no revela si
   el usuario existe o no.

----

3. Criterio de Aceptación
-------------------------

::

   DADO un usuario en pantalla de recuperación de password
   CUANDO ingresa su username
   ENTONCES el sistema valida existencia sin revelar información
   
   Escenario 1: Usuario existe y activo
   DADO username = "juan.perez" con status ACTIVE
   CUANDO se valida el username
   ENTONCES se procede a mostrar pregunta de seguridad
   
   Escenario 2: Usuario no existe
   DADO username = "usuario_falso"
   CUANDO se valida el username
   ENTONCES se muestra "Si el usuario existe, verá su pregunta de seguridad"
   Y se simula delay similar a usuario válido (timing attack prevention)
   
   Escenario 3: Usuario inactivo
   DADO username con status = INACTIVE
   CUANDO se valida el username
   ENTONCES se muestra mismo mensaje genérico
   Y NO se revela que el usuario está inactivo
   
   Escenario 4: Sin pregunta de seguridad
   DADO usuario sin pregunta de seguridad configurada
   CUANDO se valida
   ENTONCES se muestra "Contacte al administrador para recuperar acceso"

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:**
  - CNST-005: Seguridad DRF (no revelar existencia de usuarios)

**Consideraciones de Seguridad:**

- Tiempo de respuesta constante (~500ms) para todos los casos
- Rate limiting: máximo 5 intentos por IP en 15 minutos
- Logging de intentos sin revelar resultado en logs públicos
