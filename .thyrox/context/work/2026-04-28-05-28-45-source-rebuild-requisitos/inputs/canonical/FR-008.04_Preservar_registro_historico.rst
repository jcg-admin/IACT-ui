FR-008.04: Preservar registro histórico
=======================================

2. Especificación
-----------------

**Declaración:**

   El sistema DEBE preservar el registro completo del usuario y registrar
   evento de auditoría CUANDO se completa la baja lógica (BR_009).

**Descripción:**

   Preservación de datos:
   
   **Datos del Usuario Preservados:**
   
   - Todos los campos del registro original
   - Historial de passwords (hashes)
   - Historial de modificaciones previas
   - Asignaciones de roles (históricas)
   - Registros de auditoría relacionados
   
   **Evento de Auditoría:**
   
   - ``event_type``: 'USER_DEACTIVATED'
   - ``actor_user_id``: ID del admin
   - ``target_user_id``: ID del usuario dado de baja
   - ``details``: motivo, fecha, sesiones cerradas
   
   **Retención:**
   
   Los registros de usuarios inactivos se retienen indefinidamente
   para cumplimiento y auditoría.

----

3. Criterio de Aceptación
-------------------------

::

   DADO una baja de usuario completada
   CUANDO se finaliza la transacción
   ENTONCES el registro y la auditoría quedan preservados
   
   Escenario 1: Registro completo preservado
   DADO usuario "juan.perez" dado de baja
   CUANDO se consulta después de la baja
   ENTONCES todos los datos originales existen
   Y status = 'INACTIVE'
   Y se puede ver historial completo
   
   Escenario 2: Auditoría de baja
   DADO baja completada
   CUANDO se consulta auditoría
   ENTONCES existe registro USER_DEACTIVATED
   Y contiene motivo de baja
   Y contiene quién ejecutó la baja
   
   Escenario 3: Referencias intactas
   DADO usuario dado de baja con registros de auditoría previos
   CUANDO se consultan esos registros
   ENTONCES las referencias al usuario siguen funcionando
   Y se puede ver el nombre/username del usuario
   
   Escenario 4: Reportes incluyen inactivos
   DADO reporte de usuarios con opción "incluir inactivos"
   CUANDO se genera
   ENTONCES aparecen usuarios dados de baja
   Y se marca visualmente como INACTIVE

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:**
  - BR_009: Solo bajas lógicas (preservación obligatoria)
  
- **CNST aplicables:**
  - CNST-006: Políticas de retención
  - CNST-009: Auditoría inmutable

**Prohibiciones:**

- NUNCA ejecutar DELETE físico de usuarios
- NUNCA anonimizar datos sin aprobación legal
- NUNCA truncar historial de auditoría
