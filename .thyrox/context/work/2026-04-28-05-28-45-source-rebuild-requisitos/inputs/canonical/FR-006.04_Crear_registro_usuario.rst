2. Especificación
-----------------

**Declaración:**

   El sistema DEBE crear un nuevo registro en la tabla users con todos
   los datos proporcionados CUANDO las validaciones han sido exitosas.

**Descripción:**

   El registro incluye los siguientes campos:
   
   **Campos del Usuario:**
   
   .. list-table::
      :widths: 25 20 55
      :header-rows: 1
   
      * - Campo
        - Tipo
        - Valor
      * - id
        - UUID
        - Generado automáticamente
      * - username
        - VARCHAR(50)
        - Normalizado (lowercase)
      * - full_name
        - VARCHAR(100)
        - Como fue ingresado
      * - email
        - VARCHAR(100)
        - Normalizado (lowercase)
      * - password_hash
        - VARCHAR(255)
        - Hash bcrypt del temporal
      * - security_question
        - VARCHAR(200)
        - Pregunta seleccionada
      * - security_answer_hash
        - VARCHAR(255)
        - Hash de respuesta
      * - status
        - ENUM
        - 'ACTIVE'
      * - must_change_password
        - BOOLEAN
        - true
      * - created_at
        - TIMESTAMP
        - NOW()
      * - created_by
        - UUID
        - ID del admin creador

----

3. Criterio de Aceptación
-------------------------

::

   DADO todos los datos validados y password generado
   CUANDO el sistema crea el registro
   ENTONCES el usuario queda registrado en BD
   
   Escenario 1: Creación exitosa
   DADO datos completos y válidos
   CUANDO se ejecuta INSERT
   ENTONCES existe registro en tabla users
   Y status = 'ACTIVE'
   Y must_change_password = true
   Y created_by = ID del admin actual
   
   Escenario 2: UUID único
   DADO múltiples usuarios creados
   CUANDO se generan IDs
   ENTONCES cada usuario tiene UUID único
   
   Escenario 3: Transacción atómica
   DADO error durante creación
   CUANDO falla algún paso
   ENTONCES se hace rollback completo
   Y no queda registro parcial
   
   Escenario 4: Timestamps automáticos
   DADO usuario recién creado
   CUANDO se consulta
   ENTONCES created_at tiene fecha/hora actual
   Y updated_at = created_at

----

4. Reglas y Restricciones
-------------------------

- Constraint UNIQUE en ``username`` (lowercase)
- Constraint UNIQUE en ``email`` (lowercase)
