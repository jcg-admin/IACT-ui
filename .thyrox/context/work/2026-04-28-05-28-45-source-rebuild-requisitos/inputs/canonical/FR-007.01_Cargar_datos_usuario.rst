2. Especificación
-----------------

**Declaración:**

   El sistema DEBE cargar y mostrar los datos actuales del usuario
   CUANDO el administrador selecciona un usuario para modificar.

**Descripción:**

   El sistema presenta:
   
   **Campos Editables:**
   
   - Nombre completo
   - Email interno
   - Estado (ACTIVE/INACTIVE)
   - Pregunta de seguridad
   - Respuesta de seguridad (campo vacío, solo para cambiar)
   
   **Campos Solo Lectura:**
   
   - Username (inmutable)
   - ID de usuario
   - Fecha de creación
   - Creado por
   - Último login
   - Fecha última modificación
   
   **Información Adicional:**
   
   - Roles asignados (referencia a UC de Access)
   - Segmento asignado
   - Sesiones activas (conteo)

----

3. Criterio de Aceptación
-------------------------

::

   DADO un administrador buscando usuario
   CUANDO selecciona un usuario para editar
   ENTONCES se cargan todos los datos en formulario
   
   Escenario 1: Carga exitosa
   DADO usuario existente con ID = "abc-123"
   CUANDO se carga para edición
   ENTONCES todos los campos editables están poblados
   Y campos solo lectura están visibles pero deshabilitados
   
   Escenario 2: Username inmutable
   DADO formulario de edición cargado
   CUANDO se inspecciona campo username
   ENTONCES está visible pero no editable
   Y tiene indicador visual de "no modificable"
   
   Escenario 3: Usuario no encontrado
   DADO búsqueda de usuario inexistente
   CUANDO se ejecuta la búsqueda
   ENTONCES se muestra "Usuario no encontrado"
   
   Escenario 4: Información de contexto
   DADO usuario cargado para edición
   CUANDO se ve el formulario
   ENTONCES se muestra roles actuales (solo lectura)
   Y se muestra segmento asignado

----

4. Reglas y Restricciones
-------------------------

- **BR aplicables:** Ninguna específica
  
- **CNST aplicables:** Ninguna específica

**Permisos:**

El administrador solo puede ver/editar usuarios según su propio
segmento, a menos que tenga permisos de admin global.
